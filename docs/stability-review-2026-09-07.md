# Проверка стабильности — 7 сентября 2026

Базовая ревизия: `525d8fd8a1dc98327287b681c490a86bbf867636` (v12.9.2.260).

## Ограничение результата

Получено сообщение о вылетах, но нет crash-log, модели iPhone, версии iOS и точного сценария. Причина вылета не подтверждена; успешная сборка не доказывает отсутствие runtime-ошибок. Это целевая проверка доработок, не аудит каждого файла Telegram и не гарантия отсутствия всех багов.

## Изменения

1. **Удаление внешней проверки даты.** Из строки регистрации убраны запросы к AyuGram, кэш, подписки, диалоги и обновление layout после сетевого ответа. Только пассивный показ месяца Telegram / «Нет данных». Старый расчёт по ID не возвращается.
2. **Подтверждённый дефект обновления иконок.** `telewhiteThemeModsUpdated` кодировал только стили 1–3. Значения 0, 4, 5, 6 давали одинаковый набор флагов, поэтому `distinctUntilChanged` подавлял переключение между ними. Добавлены флаги 4–6 с сохранением прежних позиций остальных флагов.
3. **Подтверждённый пропуск в ключе кэша иконок.** `telewhiteRenderSettingsSymbolIcon` принимает размер, но ключ кэша его не включал. Один символ разного размера мог получить чужой результат. Размер добавлен в ключ.
4. **Защитная правка кэша мод-меню.** Неограниченный изменяемый словарь заменён на потокобезопасный NSCache с лимитом 100. Это устраняет риск конкурентного доступа и неограниченного накопления цветов, но не является доказанной причиной жалобы.

## Что проверено

- Строка профиля и отсутствие повторяющихся ID в пользовательском блоке.
- Валидация месяца, форматирование и граничные значения в Swift.
- Настройки модов: сохранённые ключи, порядок и уникальность ID строк на 12 экранах; статическая проверка добавлена в репозиторий.
- Механизм обновления тем/иконок и два кэша изображений.
- AMOLED-преобразование: применяется только к тёмным темам, уведомления фильтруются от повторов.
- Атрибут удалённого сообщения: сериализация timestamp с безопасным значением по умолчанию.
- Механизм фоновых импульсов невидимки (см. отдельное замечание ниже).

## Требует отдельной проверки

- В `TelewhitePresenceGuard` один общий таймер `shared` и один deadline на разные `Network`. При отправках с двух аккаунтов общий фон продолжает использовать первый Network. Кроме того, очередной импульс не перечитывает выключение невидимки. Это отдельный логический дефект; в этом исправлении сетевое поведение невидимки не меняется.
- `TelewhiteModsSettings.current` может сохранять настройки при миграции неполного набора ghost-флагов. Getter с уведомлением может приводить к повторным обновлениям; реальный краш/взаимная блокировка здесь не воспроизведены.
- Автовосстановление отправки, обработка видео, фоновые задачи iOS, многоаккаунтность и все сценарии пользовательского UI не проверены на устройстве.

## Проверка на устройстве

- Открыть/закрыть профили с включёнными и выключенными ID, с месяцем Telegram и без него; тап и долгий тап по дате ничего не запускают.
- Переключить стили иконок 0 → 4 → 5 → 6 → 0 и менять цвет темы.
- Открыть каждый экран мод-меню, включать/выключать условные пункты.
- Если вылет сохраняется, сохранить .ips из «Настройки iOS → Конфиденциальность и безопасность → Аналитика и улучшения → Данные аналитики». Нужен файл Telewhite/Telegram за момент вылета. Перед передачей можно скрыть личные пути и идентификаторы.
- Уточнить, установлен sideload-IPA или extensions-IPA. Последний требует подписи с нужными entitlements/app group; это отдельный возможный источник проблем запуска.

Не удалять приложение и не выходить из аккаунта ради диагностики: это может потерять локальные данные и текущую авторизацию.
